# Contract: вызовы `ibcmd`

**Feature**: [spec.md](../spec.md) | **Plan**: [plan.md](../plan.md) | **Research**: [research.md](../research.md)

Все команды запускаются через `ProcessBuilder` с абсолютными путями, объединённым stdout+stderr, потоковым выводом в консоль и поддержкой отмены (уничтожение процесса). Пароли и иные секреты маскируются в выводе, логах и отчётах.

## Общие параметры (все команды)

```text
<ibcmd> infobase --data=<tmp>/server-data --temp=<tmp>/server-temp --db-path=<IB path> <command> ...
```

- `<ibcmd>` — `<каталог толстого клиента>/ibcmd` (Windows: `<каталог>/bin/ibcmd.exe`); из `PATH` не берётся.
- `--data` — приватный временный каталог, **не** общий `~/.1cv8/.../standalone-server/` (иначе «Ошибка блокировки каталога данных сервера», проверено).
- `--user=<user> --password=<password>` — только если в настройках ИБ EDT заданы учётные данные; значения маскируются.
- `--db-path` — путь файловой ИБ из привязанного приложения.

## Полная загрузка

```text
1) <ibcmd> infobase ... config import <xmlDir>
2) <ibcmd> infobase ... config apply
```

- `<xmlDir>` — каталог, полученный экспортом EDT (`Configuration.xml`, `ConfigDumpInfo.xml`, объекты).
- Успех: код 0 обеих команд. Неуспех импорта → `config apply` не выполняется.

## Частичная загрузка

```text
1) <ibcmd> infobase ... config import files --partial --base-dir=<xmlDir> <relFile1> ... <relFileN>
2) <ibcmd> infobase ... config apply
```

- `<relFileN>` — XML-файлы изменённых объектов относительно `<xmlDir>` (из результата экспорта изменённых объектов).
- `--base-dir` — корень выгрузки; пути передаются относительно него.
- Fallback: если change set содержит удаление/переименование — выполняется полная загрузка (см. контракт команды), пользователь уведомлён.

## Подтверждение предупреждений при apply

```text
<ibcmd> infobase ... config apply --force    # только после явного подтверждения пользователя
```

- `--force` передаётся только для `config apply` и только после диалога подтверждения; один повтор.
- `--session-terminate=force` не передаётся никогда; сеансы пользователей не завершаются.
- Признак «нужно подтверждение»: ненулевой код возврата apply и/или текст предупреждений в выводе (правило уточняется в реализации по реальному поведению 8.3.27).

## Получение состояния конфигурации для EDT

```text
<ibcmd> infobase ... config export info --out=<tmp>/dump
```

- Результат: `<tmp>/dump/ConfigDumpInfo.xml` (проверено; `--out` — каталог, а не файл).
- Используется для `IUpdateInfobaseFlow#loadActualConfigDumpInfo` после успешных import+apply.

## Коды возврата и отмена

| Случай | Обработка |
|--------|-----------|
| код 0 | успех стадии |
| код != 0 | стадия неуспешна; показать вывод и код; не выполнять следующие стадии; состояние синхронизации не обновлять |
| отмена пользователем | процесс уничтожить; стадия = `CANCELLED`; последующие стадии не выполнять |
| apply неуспешен из-за предупреждений | запрос подтверждения → повтор с `--force`; при отказе/повторе-неуспехе — ошибка, синхронизация не обновляется |
| процесс не запустился (нет файла/прав) | preflight-ошибка `ibcmd недоступен` |

## Временные каталоги

- `<tmp>` — уникальный каталог на операцию (`Files.createTempDirectory`).
- Структура: `<tmp>/server-data`, `<tmp>/server-temp`, `<tmp>/xml`, `<tmp>/dump`.
- Удаление — всегда (`finally`), в том числе при ошибке и отмене; удаление не должно маскировать исходную ошибку.

## Запрещено

- `infobase create`, `--session-terminate=force`, `--force` для импорта, молчаливое использование произвольного `ibcmd`, логирование паролей, изменение файлов проекта.
