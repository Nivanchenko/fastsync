# Feature Specification: Загрузка исходников проекта EDT в файловую ИБ через ibcmd

**Feature Branch**: `vendor/example` (текущая ветка; отдельная feature-ветка не создавалась)

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: [task.md](../../task.md) — отдельная команда загрузки исходников проекта 1C:EDT в привязанную файловую информационную базу через `ibcmd`, с полной и частичной загрузкой, безопасной работой с сеансом агента Конфигуратора и обновлением состояния синхронизации EDT.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Полная загрузка исходников в привязанную файловую ИБ (Priority: P1)

Разработчик открывает проект EDT, привязанный к существующей файловой информационной базе, явно запускает отдельную команду загрузки, выбирает полную загрузку и получает в ИБ актуальную конфигурацию, соответствующую исходникам проекта. После операции штатная загрузка EDT не должна предлагать повторно загрузить те же изменения.

**Why this priority**: Это основная ценность фичи и минимально жизнеспособный сценарий; без него остальные сценарии не имеют смысла.

**Independent Test**: Проект с привязанной файловой ИБ, установленной платформой с `ibcmd`; изменить один объект метаданных, выполнить команду (полная загрузка) и проверить, что конфигурация ИБ обновилась, а штатная загрузка EDT не показывает несинхронизированных изменений.

**Acceptance Scenarios**:

1. **Given** проект с привязанным приложением файловой ИБ и доступным `ibcmd` в требуемой версии платформы, **When** пользователь запускает команду и выбирает полную загрузку, **Then** плагин выполняет проверки, сохраняет проект, конвертирует исходники, импортирует конфигурацию в существующую ИБ, применяет её и сообщает об успехе.
2. **Given** успешная полная загрузка, **When** пользователь повторно открывает штатный механизм загрузки/сравнения EDT, **Then** ранее загруженные изменения не считаются несинхронизированными.
3. **Given** исходники проекта, **When** плагин конвертирует их во временный формат, **Then** файлы проекта не изменяются.

### User Story 2 - Частичная загрузка только несинхронизированных изменений (Priority: P2)

Разработчик выбирает частичную загрузку, и плагин переносит в ИБ только те изменения проекта, которые EDT считает несинхронизированными, после чего применяет конфигурацию. Если среди изменений есть удаление или переименование объектов, плагин вместо частичного импорта выполняет полную загрузку и сообщает об этом.

**Why this priority**: Частичная загрузка заметно ускоряет типовой цикл разработки, но полная загрузка уже покрывает корректность; частичную можно поставлять отдельным шагом.

**Independent Test**: Изменить один объект метаданных, выполнить частичную загрузку и убедиться, что итоговое состояние ИБ совпадает с результатом полной загрузки для того же набора изменений, а при удалении/переименовании — выполняется полная загрузка с сообщением.

**Acceptance Scenarios**:

1. **Given** непустой набор несинхронизированных изменений без удалений и переименований, **When** пользователь выбирает частичную загрузку, **Then** плагин импортирует только изменённые файлы в частичном режиме и применяет конфигурацию.
2. **Given** несинхронизированные изменения содержат удаление или переименование объекта, **When** пользователь выбирает частичную загрузку, **Then** плагин выполняет полную загрузку и явно сообщает причину.
3. **Given** несинхронизированных изменений нет, **When** пользователь выбирает частичную загрузку, **Then** плагин сообщает, что загружать нечего, и не изменяет ИБ.

### User Story 3 - Безопасный отказ и работа с сеансом агента Конфигуратора (Priority: P2)

Перед обращением к базе плагин проверяет, что приложение привязано, база файловая, версия платформы определена, `ibcmd` доступен. Если продолжить нельзя, база не изменяется, а пользователь получает понятное сообщение. Если открыт сеанс агента Конфигуратора, удерживающий блокировку базы, плагин закрывает подключение публичным API EDT и восстанавливает исходное состояние после операции.

**Why this priority**: Без этих проверок фича опасна для пользовательских баз; корректность отказа — часть контракта, а не улучшение.

**Independent Test**: Набор негативных проверок (нет приложения, не ИБ, база не файловая, нет платформы, нет `ibcmd`) — каждая прерывает операцию без изменения базы; отдельно — открытый сеанс агента закрывается и восстанавливается после успеха, ошибки и отмены.

**Acceptance Scenarios**:

1. **Given** у проекта нет привязанного приложения, приложение не является приложением ИБ, база не файловая, подходящая платформа не найдена или `ibcmd` отсутствует, **When** пользователь запускает команду, **Then** загрузка не начинается, ИБ не изменяется, пользователь получает понятное сообщение с причиной.
2. **Given** открыт сеанс агента Конфигуратора для целевой ИБ, **When** начинается операция, **Then** плагин закрывает подключение публичным API EDT, не завершая процесс агента, и после успеха, ошибки или отмены восстанавливает исходное состояние подключения.
3. **Given** безопасно закрыть подключение или гарантированно восстановить исходное состояние нельзя, **When** пользователь запускает команду, **Then** загрузка прерывается до изменения базы.

### User Story 4 - Подтверждение предупреждений, отмена и наблюдаемость (Priority: P3)

Пользователь видит ход операции, вывод `ibcmd`, коды завершения и ошибки, может отменить операцию. Если применение конфигурации требует подтверждения предупреждений, плагин спрашивает пользователя и только после подтверждения повторяет команду с `--force`. Сеансы пользователей не завершаются принудительно, секреты не попадают в логи.

**Why this priority**: Влияет на доверие и управляемость, но не на базовую корректность загрузки.

**Independent Test**: Спровоцировать предупреждение при применении конфигурации, отказаться от `--force` и проверить, что плагин не применяет конфигурацию и не считает проект синхронизированным; отдельно — отмена на разных стадиях и проверка вывода/кодов завершения.

**Acceptance Scenarios**:

1. **Given** `config apply` требует подтверждения предупреждений, **When** пользователь отказывается от `--force`, **Then** плагин завершает операцию без применения, сообщает, что конфигурация импортирована, но не применена, и не обновляет состояние синхронизации.
2. **Given** идёт операция, **When** пользователь нажимает «Отмена», **Then** операция останавливается на ближайшей безопасной границе, подключение агента восстанавливается, а итоговый отчёт честно описывает состояние базы.
3. **Given** любой запуск, **When** пользователь наблюдает за операцией, **Then** ему доступны выполняемые команды `ibcmd`, их вывод, коды завершения и ошибки; пароли и другие секреты не логируются.
4. **Given** применение конфигурации требует завершения сеансов, **When** плагин выполняет `config apply`, **Then** он не передаёт `--session-terminate=force` и не завершает сеансы пользователей автоматически, а сообщает о блокировке.

### Edge Cases

- У проекта несколько приложений или приложение не выбрано по умолчанию — плагин использует приложение по умолчанию; если его нет, отказывает с сообщением.
- Требуемая версия платформы не задана, не установлена или подходит несколько установок — плагин отказывает до изменения базы.
- `ibcmd` отсутствует в установленной платформе (старая версия платформы) — загрузка не начинается.
- Путь к ИБ не существует, недоступен, указывает не на файловую базу или база заблокирована другим процессом — плагин сообщает причину, не изменяя базу.
- В проекте есть несохранённые изменения — плагин сохраняет их перед конвертацией; ошибка сохранения прерывает операцию.
- Временный каталог конвертации удаляется при успехе, ошибке и отмене.
- Пути проекта и ИБ содержат пробелы и не-ASCII символы (кириллица) — операция работает корректно.
- Частичный набор изменений пуст — операция не обращается к базе (см. US2).
- Изменения содержат удаление или переименование одновременно с другими изменениями — выполняется полная загрузка.
- `ibcmd` завершился с ненулевым кодом, аварийно или при нехватке места — плагин показывает вывод и код, не выполняет `apply` и не обновляет состояние синхронизации.
- Отмена после успешного импорта, но до `apply` — плагин сообщает, что конфигурация импортирована, но не применена.
- Пользователь закрывает проект во время операции — операция отменяется с восстановлением сеанса агента.
- Повторный запуск команды для проекта, где уже идёт загрузка, — второй запуск отклоняется.
- Сеанс агента уже был закрыт до операции — восстанавливать нечего; если был открыт — восстанавливается именно открытое состояние.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Плагин ДОЛЖЕН предоставлять отдельную явную команду загрузки для проекта, не перехватывающую и не заменяющую штатную загрузку EDT.
- **FR-002**: Команда ДОЛЖНА позволять пользователю выбрать полную или частичную загрузку; режим не выбирается молча.
- **FR-003**: Целевая ИБ и версия платформы ДОЛЖНЫ определяться только по выбранному приложению проекта; при нескольких приложениях команда доступна в контекстном меню каждого приложения (обновляется именно его ИБ), а при запуске из проекта используется приложение по умолчанию, которое явно показывается пользователю. Плагин НЕ ДОЛЖЕН использовать произвольный `ibcmd` из `PATH` или другую базу.
- **FR-004**: Перед любым изменением базы плагин ДОЛЖЕН проверить: наличие привязанного приложения, что это приложение ИБ, что база файловая, что требуемая версия платформы однозначно определена и найдена установка, что в ней доступен `ibcmd`.
- **FR-005**: При провале проверок загрузка НЕ ДОЛЖНА начинаться; база не изменяется; пользователь получает понятное сообщение о причине и способе исправления.
- **FR-006**: Плагин НЕ ДОЛЖЕН использовать команду создания ИБ (`infobase create`); допускается импорт только в существующую ИБ.
- **FR-007**: Перед конвертацией плагин ДОЛЖЕН сохранить актуальное состояние проекта.
- **FR-008**: Плагин ДОЛЖЕН конвертировать исходники проекта средствами EDT во временный формат, принимаемый `ibcmd`; исходные файлы проекта НЕ ДОЛЖНЫ изменяться конвертацией; временные данные удаляются после операции.
- **FR-009**: До обращения к базе плагин ДОЛЖЕН определить, открыт ли сеанс агента Конфигуратора для целевой ИБ, и при необходимости закрыть подключение публичным API EDT, не завершая процесс агента.
- **FR-010**: Исходное состояние подключения агента ДОЛЖНО восстанавливаться при успехе, ошибке и отмене.
- **FR-011**: Если безопасно закрыть подключение или гарантированно восстановить исходное состояние нельзя, загрузка ДОЛЖНА быть прервана до изменения базы.
- **FR-012**: Полная загрузка ДОЛЖНА импортировать всю конвертированную конфигурацию в существующую ИБ и затем автоматически выполнить применение конфигурации (`config apply`).
- **FR-013**: Частичная загрузка ДОЛЖНА получать набор несинхронизированных изменений проекта средствами EDT, импортировать изменённые файлы в частичном режиме (`config import files` / `--partial`) и затем применять конфигурацию.
- **FR-014**: Если частичные изменения содержат удаление или переименование объектов, плагин ДОЛЖЕН вместо частичного импорта выполнить полную загрузку и сообщить об этом пользователю.
- **FR-015**: Плагин НЕ ДОЛЖЕН молча использовать `--force`. Если применение конфигурации требует подтверждения предупреждений, плагин ДОЛЖЕН запросить подтверждение пользователя и только после него повторить команду с `--force`.
- **FR-016**: Плагин НЕ ДОЛЖЕН задавать `--session-terminate=force` и автоматически завершать сеансы пользователей; при невозможности применить конфигурацию из-за сеансов операция завершается с понятным сообщением.
- **FR-017**: Применение конфигурации ДОЛЖНО выполняться только после успешного импорта.
- **FR-018**: После успешной загрузки плагин ДОЛЖЕН обновить внутреннее состояние EDT через публичный API так, чтобы штатная загрузка не считала загруженные изменения несинхронизированными.
- **FR-019**: Если публичного API для обновления состояния синхронизации нет, операцию НЕЛЬЗЯ считать выполненной; плагин обязан сообщить об ошибке и не оставлять состояние синхронизации молча неконсистентным.
- **FR-020**: Ход выполнения, выполняемые команды `ibcmd`, их вывод, коды завершения, отмена и ошибки ДОЛЖНЫ быть доступны пользователю в EDT.
- **FR-021**: Пароли и другие секреты НЕ ДОЛЖНЫ записываться в логи, вывод и отчёты; риск кратковременной видимости пароля как аргумента процесса ДОЛЖЕН быть учтён и минимизирован.
- **FR-022**: Пользователь ДОЛЖЕН иметь возможность отменить операцию на любой стадии; отмена завершает операцию на безопасной границе, восстанавливает подключение агента и отражается в итоговом отчёте.
- **FR-023**: Итоговый отчёт ДОЛЖЕН честно описывать результат: режим, целевую базу, что именно импортировано и применено, код завершения и что осталось несделанным.
- **FR-024**: Плагин ДОЛЖЕН разрешать не более одной операции загрузки на проект одновременно; повторный запуск во время операции отклоняется.
- **FR-025**: Команда ДОЛЖНА работать через публичные API EDT; использование внутренних API допускается только после отдельного обоснования и согласования.
- **FR-026**: Пользовательские строки ДОЛЖНЫ выноситься в локализуемые ресурсы плагина в соответствии с конвенциями репозитория.

### Key Entities *(include if feature involves data)*

- **Проект EDT**: открытый проект разработки; источник исходников и точка привязки приложения.
- **Приложение проекта**: привязанное приложение (по умолчанию); определяет ИБ, тип базы и требуемую версию платформы.
- **Файловая информационная база**: существующая целевая база; путь, доступность, состояние блокировки и подключения агента Конфигуратора.
- **Установка платформы 1С:Предприятие**: найденная по требуемой версии; наличие и версия `ibcmd`.
- **Набор изменений**: полный или частичный; состав изменённых файлов, наличие удалений/переименований.
- **Операция загрузки**: режим, текущая стадия, статус, вывод и коды завершения, время.
- **Состояние синхронизации проекта и ИБ**: равенство конфигураций и признак «есть несинхронизированные изменения» в EDT.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После полной загрузки и применения конфигурации штатная загрузка EDT не предлагает загрузить те же изменения; проверено на EDT 2026.2.2 и файловой ИБ платформы 8.3.27.
- **SC-002**: Для одного и того же набора изменений частичная загрузка приводит к тому же итоговому состоянию ИБ, что и полная (кроме случаев удаления/переименования, где выполняется полная загрузка).
- **SC-003**: 100% негативных проверок (нет приложения, не приложение ИБ, база не файловая, нет платформы, нет `ibcmd`) прерывают операцию без изменения базы и дают понятное сообщение.
- **SC-004**: В 100% прогонов (успех, ошибка, отмена) состояние подключения агента Конфигуратора после операции совпадает с состоянием до неё.
- **SC-005**: Ноль запусков `--force` без явного подтверждения пользователя; ноль случаев `--session-terminate=force` и принудительного завершения сеансов.
- **SC-006**: Отмена на любой стадии срабатывает и даёт итоговый отчёт, честно описывающий состояние базы.
- **SC-007**: После конвертации файлы проекта побайтово не изменены, временные данные не остаются.
- **SC-008**: Ни одно значение пароля или иного секрета не встречается в собранном выводе, логах и отчётах.
- **SC-009**: Пользователь видит каждую команду `ibcmd`, её вывод и код завершения при каждом запуске.
- **SC-010**: Фича собирается и работает в целевой среде EDT 2026.2.2; все решения, заимствованные из прошлых попыток, перепроверены на этой версии.

## Assumptions

- **Целевая среда** — 1C:EDT 2026.2.2 (установленная сборка 2026.2.2.21) на Java 25, построена на Eclipse 2025-12; это единственная целевая версия проекта, `AGENTS.md` и документация репозитория приведены к ней.
- **Наработки прошлых попыток** (ветка `main`) сделаны для более старой среды и после смены целевой версии не являются основанием для проектных решений; проверка публичных API, версий и сценариев выполнена на EDT 2026.2.2.
- Поддерживается только **существующая файловая** ИБ; клиент-серверные, удалённые и вновь создаваемые базы вне объёма.
- Если команда запущена из проекта, а приложений несколько, используется приложение по умолчанию (и показывается в диалоге); точечно обновить конкретную ИБ можно командой из контекстного меню приложения. Если приложения по умолчанию нет — операция не начинается.
- `ibcmd` считается доступным, если он присутствует в установке платформы, однозначно найденной по требуемой версии приложения (для используемой платформы 8.3.27 `ibcmd` есть).
- Файловая ИБ в типовом случае не требует аутентификации. Если учётные данные нужны, они берутся из настроек ИБ в EDT; пароль передаётся CLI-аргументом (ограничение платформы), маскируется в выводе и не логируется.
- Частичная загрузка переносит только изменения конфигурации (метаданных); миграция данных не выполняется.
- Переименования с сохранённым UUID распознаёт платформа при применении конфигурации; плагин только определяет необходимость полной загрузки.
- Плагин не блокирует редактирование проекта пользователем во время операции; сохранение выполняется до конвертации.
- Отмена после импорта может оставить ИБ с импортированной, но не применённой конфигурацией; это допустимо при честном отчёте пользователю.
- Публичные API EDT 2026.2.2 для привязки приложения к ИБ, работы с установками платформы, открытия/закрытия сеанса агента Конфигуратора, экспорта исходников и состояния синхронизации существуют; это подтверждено предварительной проверкой и является обязательным условием приёмки.
- Стандартная загрузка EDT сохраняется; плагин дополняет её отдельной командой.
