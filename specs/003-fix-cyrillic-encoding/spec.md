## User Scenarios & Testing *(mandatory)*

### User Story 1 - Понятное русское название плагина в менеджере установки (Priority: P1)

Пользователь с русским интерфейсом EDT добавляет каталог обновлений, открывает **Help → Install New Software** и видит в списке компонент с читаемым русским названием и описанием («FastSync для 1C:EDT», «Плагин FastSync для 1C:EDT.»). После установки в **Help → Installation Details** название плагина тоже читаемое, без символов вида «Ð»/«Ñ» и «?».

**Why this priority**: Сейчас пользователь не понимает, что именно устанавливает: название превращается в набор нечитаемых символов. Это первое, что видит новый пользователь, поэтому дефект бьёт по доверию и по установке.

**Independent Test**: Собрать каталог обновлений, добавить его в чистую EDT с русским интерфейсом, открыть список компонентов и страницу сведений об установке. Проверка самостоятельна и не требует запуска загрузки в базу.

**Acceptance Scenarios**:

1. **Given** чистая EDT с русским интерфейсом и каталог обновлений новой сборки, **When** пользователь открывает **Install New Software**, **Then** название компонента читается как «FastSync для 1C:EDT», описание — «Плагин FastSync для 1C:EDT.»; символов «Ð», «Ñ», «?» и других признаков искажения нет.
2. **Given** плагин установлен из этого каталога, **When** пользователь открывает **Help → Installation Details**, **Then** название установленного плагина отображается по-русски без искажений.
3. **Given** интерфейс EDT переключён на английский, **When** пользователь открывает список компонентов, **Then** название и описание остаются английскими («FastSync for 1C:EDT») и не меняются относительно текущего поведения.

### User Story 2 - Читаемая кириллица в консоли FastSync на Windows (Priority: P1)

Пользователь на Windows с русской локалью (системная кодировка по умолчанию отлична от UTF-8) запускает загрузку исходников и видит в консоли FastSync нормальный русский текст: строки плагина («Запуск: …», «Импорт конфигурации», итог операции), строку команды `ibcmd`, предупреждения `ibcmd` и пути к файлам проекта с кириллицей. Сейчас вместо этого видно «Р—Р°РїСѓСЃРє…», а часть букв заменена на «?» или ромбы.

**Why this priority**: Консоль — единственное место, где пользователь видит, что происходит с его рабочей базой. Некорректный вывод делает диагностику невозможной, а ошибки `ibcmd` с русскими путями — нечитаемыми; это блокирует работу основной группы пользователей (Windows).

**Independent Test**: На Windows с русской локалью выполнить загрузку на файловой ИБ и просмотреть консоль FastSync: все русские строки, включая пути с кириллицей из вывода `ibcmd`, читаемы. Проверка не требует правок в базе за пределами тестовой ИБ.

**Acceptance Scenarios**:

1. **Given** Windows с системной кодировкой, отличной от UTF-8, **When** пользователь запускает загрузку, **Then** все строки консоли на русском читаемы: нет последовательностей «Ð…», «Ñ…», ромбов и «?» вместо букв.
2. **Given** в путях проекта или базы есть кириллица, **When** `ibcmd` выводит предупреждения с этими путями, **Then** пути в консоли отображаются правильно.
3. **Given** macOS или Linux (UTF-8 по умолчанию), **When** пользователь запускает загрузку, **Then** кириллица в консоли отображается правильно, то есть регрессии относительно текущего поведения нет.
4. **Given** Windows с английской локалью, **When** пользователь запускает загрузку, **Then** вывод не содержит искажений (латиница и служебные строки не меняются).

### User Story 3 - Русские подписи плагина и отчёт без искажений при любой кодировке по умолчанию (Priority: P2)

Пользователь на любой ОС видит корректные русские подписи во всех точках интерфейса плагина: пункт контекстного меню «Загрузить исходники в ИБ через ibcmd», заголовок консоли, диалоги результата и текст итогового отчёта. Строки не зависят от того, какая кодировка выбрана в системе или JVM по умолчанию.

**Why this priority**: Все эти строки происходят из того же слоя локализации, что и название плагина; если исправлять только установщик или только консоль, часть интерфейса останется хрупкой и при смене окружения снова «поедет».

**Independent Test**: Пройти полный сценарий загрузки (успех, ошибка, отмена) и просмотреть меню, заголовок консоли, диалоги и отчёт на предмет битых символов; повторить на окружении с не-UTF-8 кодировкой по умолчанию.

**Acceptance Scenarios**:

1. **Given** русский интерфейс EDT, **When** пользователь открывает контекстное меню проекта, **Then** пункт загрузки называется «Загрузить исходники в ИБ через ibcmd» без искажений.
2. **Given** загрузка завершилась успешно, ошибкой или была отменена, **When** пользователь читает диалог и отчёт, **Then** все русские строки, включая названия стадий и причину ошибки, читаемы.
3. **Given** окружение с кодировкой по умолчанию, отличной от UTF-8, **When** пользователь работает с плагином, **Then** подписи меню, консоли и диалогов не меняются по сравнению с UTF-8-окружением.

---

### Edge Cases

- Системная кодировка Windows — cp866 (консоль `cmd`) или cp1251 (ANSI): кириллица должна быть читаема в обоих случаях.
- В одной строке смешаны кириллица, латиница и типографские символы (длинное тире, знак номера, кавычки-ёлочки, стрелка): искажений нет ни в одной части.
- Кириллические имена проектов и информационных баз в строке команды, в отчёте и в Error Log: отображаются правильно.
- Маскирование пароля в консоли и отчёте продолжает работать: замена на «***» не затрагивается исправлением.
- Переключение языка интерфейса EDT между русским и английским: каждая локаль показывает свои строки без «смешивания» и без искажений.
- Обновление ранее установленного плагина: после установки новой сборки из каталога обновлений название исправлено (пользователю не нужно переустанавливать вручную).
- Строки, которые плагин передаёт в Error Log и диалоги, остаются теми же по смыслу и составу — меняется только корректность отображения.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Все локализуемые пользовательские строки плагина MUST читаться одинаково корректно всеми потребителями: каталогом обновлений (менеджер установки), платформой и кодом плагина (сообщения, меню, консоль, отчёты) — независимо от кодировки по умолчанию ОС и JVM.
- **FR-002**: Название, описание и поставщик компонента в менеджере установки и в сведениях об установке MUST отображаться на языке интерфейса EDT без искажений (для русского — «FastSync для 1C:EDT», «Плагин FastSync для 1C:EDT.»).
- **FR-003**: Консоль FastSync MUST отображать без искажений сообщения плагина, строку выполняемой команды, вывод `ibcmd` и пути с кириллицей при системной кодировке, отличной от UTF-8 (windows-1251, cp866, cp1252).
- **FR-004**: Подписи меню, заголовок консоли, диалоги результата и текст отчёта MUST отображаться без искажений при любой кодировке по умолчанию ОС/JVM.
- **FR-005**: Исправление MUST NOT менять состав, порядок и смысл выводимых строк, а также MUST NOT ослаблять маскирование секретов в консоли, отчётах и Error Log.
- **FR-006**: Для исправленного поведения MUST быть автоматическая проверка в тестах проекта, которая обнаруживает возврат нечитаемой кириллицы в локализуемых ресурсах; существующие тесты MUST NOT ослабляться или удаляться.
- **FR-007**: Английская локаль MUST NOT измениться: английские названия и строки остаются прежними.
- **FR-008**: Правило хранения локализуемых ресурсов, исключающее повторение дефекта, MUST быть зафиксировано в документации для разработчиков.
- **FR-009**: После пересборки каталог обновлений MUST отдавать исправленные названия; обновление ранее установленного плагина MUST подхватывать исправление без ручной переустановки.

### Key Entities

- **Локализованный ресурс**: набор пользовательских строк плагина (название/описание фичи и бандла, сообщения), который читают разные потребители в разной кодировке.
- **Каталог обновлений**: источник, из которого EDT показывает и устанавливает компоненты; содержит отображаемые названия и описания.
- **Консоль операции**: окно, в которое плагин выводит команды и вывод `ibcmd` в реальном времени.
- **Отчёт операции**: итоговый текст (успех/ошибка/отмена), показываемый в диалоге и записываемый в Error Log.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В менеджере установки и в сведениях об установке 100% русских названий и описаний читаемы — проверено на чистой EDT с русским интерфейсом (0 строк с «Ð»/«Ñ»/«?»).
- **SC-002**: В консоли при системной кодировке windows-1251 100% русских строк читаемы — проверено прогоном загрузки на Windows (0 символов искажения на весь вывод операции).
- **SC-003**: Автоматическая проверка обнаруживает нечитаемую кириллицу в локализуемых ресурсах: при внесении «сырой» кириллицы проверка падает, на исправленных ресурсах — проходит.
- **SC-004**: Английский интерфейс не изменился: английские названия и строки совпадают с текущими (100% проверенных строк).
- **SC-005**: Существующие сценарии загрузки (полная, частичная, отмена, ошибка) не изменились, сборка проекта и все существующие тесты проходят.
- **SC-006**: После публикации исправленного каталога обновлений установка/обновление в EDT показывает исправленные названия без ручных действий пользователя.

## Assumptions

- Целевая среда — 1C:EDT 2026.2.2 (Java 25), Windows 10/11 с русской локалью; кириллица в путях проектов и баз допустима и поддерживается.
- `ibcmd` на целевой платформе выводит диагностику в кодировке, которая корректно декодируется текущим кодом плагина (по логу коллеги исходный русский текст восстановим, искажение возникает на отображении); задача исправляет отображение, а не перекодирует вывод `ibcmd`.
- Проверка на Windows выполняется вручную силами команды (Windows-агента в CI нет) и фиксируется в задачах фичи; локально проверяются сборка и автотесты.
- Каталог обновлений публикуется автоматически при изменении проекта; исправление доставляется пользователям через обычное обновление плагина (номер сборки при этом меняется).
- Формат хранения локализуемых ресурсов может измениться, но видимый пользователю текст остаётся прежним.
- Новых пользовательских возможностей не добавляется: фича только устраняет искажение текста и защищает от повторения.
