# Загрузка исходников в файловую ИБ через ibcmd

## Цель

Добавить в плагин FastSync для 1C:EDT отдельную команду загрузки исходников проекта в информационную базу, привязанную к проекту как приложение. Команда должна поддерживать полную и частичную загрузку через `ibcmd`, если утилита доступна в установленной для проекта версии платформы.

Команда дополняет штатную загрузку EDT, но не заменяет и не перехватывает её.

## Ограничения и исходные условия

- Поддерживается только файловая информационная база. Клиент-серверные и удалённые базы вне объёма задачи.
- Формат проекта EDT отличается от XML-формата Конфигуратора. Перед вызовом `ibcmd` исходники необходимо конвертировать средствами самой EDT.
- Плагин не реализует собственную миграцию данных: изменение структуры выполняет платформа при `config apply`. При переименовании метаданных с сохранённым UUID ожидается, что платформа распознает прежний объект; отдельная проверка и перенос записей не входят в объём плагина.
- Целевой файл базы и версия платформы определяются по приложению, привязанному к проекту; не следует молча использовать другую базу или произвольный `ibcmd` из `PATH`.
- Импорт в существующую базу не должен использовать команду создания ИБ (`infobase create`).
- Команда должна работать через публичные API EDT. Использование внутренних API — только после отдельного обоснования и согласования.

## Требуемое поведение

1. Пользователь явно запускает отдельную команду загрузки через `ibcmd` для проекта и выбирает полную или частичную загрузку.
2. Плагин проверяет привязанное приложение, тип базы, установленную версию платформы и наличие совместимого `ibcmd`. Если утилиты нет или база не файловая, загрузка не начинается; пользователь получает понятное сообщение.
3. Плагин сохраняет актуальное состояние проекта и конвертирует исходники средствами EDT во временный формат, принимаемый `ibcmd`. Исходные файлы проекта не должны изменяться конвертацией.
4. До обращения к базе плагин проверяет, открыт ли используемый EDT сеанс агента Конфигуратора (Designer Agent), который может удерживать блокировку файловой базы. Если сеанс открыт, плагин закрывает подключение публичным API EDT, а после операции восстанавливает исходное состояние — при успехе, ошибке и отмене. Сам процесс агента принудительно не завершается. Если безопасно закрыть подключение или гарантированно восстановить исходное состояние нельзя, загрузку следует прервать до изменения базы.
5. **Полная загрузка:** импортировать всю конвертированную конфигурацию в существующую ИБ, затем автоматически выполнить `ibcmd config apply`.
6. **Частичная загрузка:** получить набор несинхронизированных изменений проекта средствами EDT, импортировать изменённые файлы в частичном режиме (`config import files` / `--partial`), затем выполнить `config apply`.
7. Если частичные изменения содержат удаление или переименование объектов, вместо частичного импорта выполнить полную загрузку и сообщить об этом пользователю.
8. Не использовать `--force` молча. Если `ibcmd config apply` требует подтвердить предупреждения, запросить подтверждение пользователя в EDT и только после него повторить команду с `--force`. Не задавать `--session-terminate=force` и не завершать сеансы пользователей автоматически. Применять конфигурацию только после успешного импорта.
9. После успешной загрузки обновить внутреннее состояние EDT так, чтобы штатная загрузка не считала уже загруженные изменения несинхронизированными. Для этого найти и использовать публичный API EDT. Если такого способа нет, не считать задачу выполненной и не оставлять состояние синхронизации молча неконсистентным.
10. Вывод `ibcmd`, ход выполнения, отмена, код завершения и ошибки должны быть доступны пользователю в EDT. Не записывать пароли и другие секреты в логи. Учесть, что CLI принимает пароль как аргумент процесса, и проверить риск его кратковременной видимости другим процессам пользователя.

## Результаты предварительной проверки

- На `ibcmd` версии `8.3.27.2342` полный `infobase config import <XML-каталог>` в `build/empty_ib` завершился успешно.
- `config apply` без интерактивного подтверждения запросил принятие изменений и завершился отменой (код 102). После явного подтверждения повторный `config apply --force` успешно применил структуру базы.
- Частичный импорт `Catalogs/Аттракционы/Ext/ObjectModule.bsl` с `--base-dir=build/xml-config --partial` завершился успешно; последующий `config apply` прошёл без `--force` и создал поколение `7af82bede091764e85adc4735960f58200000000`.
- На уже заполненной `build/ib` частичный импорт того же файла и `config apply` с реквизитами пользователя завершились успешно; новое поколение: `cae22ef065f11b42838824cd67e0064200000000`. Для этих команд параметры `--user` и `--password` нужно располагать после `infobase config`.
- Свежая `build/rename_delete_empty_ib` успешно создана; полный импорт `build/xml-config-renamedelete` и `config apply --force` завершились успешно, поколение `f5d7064c14a35743a68290c0d176d31f00000000`.
- В заполненную `build/empty_ib` поверх исходной конфигурации импортирован `build/xml-config-renamedelete`; `config apply` завершился успешно без `--force`, поколение `a4744122e539614e87cdfb819d8214c300000000`.
- Экспорт конфигурации из `build/empty_ib` подтвердил, что общий модуль `Пользователи` и регистр `ПлановыеОтсутствия` отсутствуют, а `ПлановыеОтсутствияСотрудников` присутствует. UUID регистра сохранён при переименовании.
- Следовательно, `--force` для `apply` нужно включать только после отдельного подтверждения пользователя; это не должно включать принудительное завершение сеансов.
- Тестовая база `build/empty_ib` теперь содержит загруженную конфигурацию и не является пустой.

## Результаты проверки публичного API EDT

- Проверка выполнена по [P2-репозиторию EDT 2026.1](https://edt.1c.ru/downloads/releases/ruby/2026.1/), указанному в `targets/default/default.target`: просмотрены метаданные и экспортируемые пакеты bundle, сигнатуры сверены с JAR target-платформы. Публичная JavaDoc для 2026.1 по проверенному URL недоступна (404); для описания контрактов использована JavaDoc 2025.2 и сверены сигнатуры target 2026.1.
- Привязанное приложение можно получить публичным `IApplicationManager`; файловую ИБ — через `IInfobaseApplication.getInfobase()`, `InfobaseReference.getInfobaseType()` и `FileConnectionString.getFile()`. Версия приложения доступна через `IApplication.getRequiredVersion()`.
- Публичный XML-экспорт проекта доступен через `IExportOperationFactory`; корневая конфигурация получается через `IConfigurationProject.getConfiguration()`.
- Для Designer Agent найден прямой публичный API `IDesignerSessionThickClientLauncher` из экспортируемого пакета `com._1c.g5.v8.dt.platform.services.core.runtimes.execution` (bundle target 2026.1 `com._1c.g5.v8.dt.platform.services.core`, версия `23.0.2.v202609041212`):
  - `getDesignerSessionDirectory(...)` возвращает каталог подключённого сеанса или `null`, если подключения нет;
  - `closeDesignerSession(...)` закрывает подключение агента к ИБ и освобождает его для пакетных операций; контракт отдельно уточняет, что завершение процесса агента выполняется другим способом;
  - `openDesignerSession(...)` открывает, повторно подключает или использует существующий сеанс; для приложения ИБ при необходимости запускает агент.
- Следствие для требования 4: сохранить факт наличия подключения до операции; закрывать его только если оно было открыто; в `finally` повторно открыть с теми же компонентом платформы, ссылкой на ИБ и аргументами. Сеанс может быть общим для нескольких клиентов: при использовании listener нужно соблюдать контракт повторного использования listener и учитывать уведомления о разрыве/переподключении. Этот сценарий ещё требует проверки в запущенной EDT на тестовой ИБ.
- В том же API есть `IThickClientLauncher` с импортом/экспортом XML и `retrieveInfobaseChanges`, но последний сравнивает конфигурацию ИБ с `ConfigDumpInfo.xml`; это не список несинхронизированных файлов проекта EDT и не замена `ibcmd` в этой задаче.
- `IApplicationManager.getUpdateState()` сообщает статус загрузки приложения, а `update(...)` сам загружает конфигурацию из проекта в ИБ. Публичный API для простого подтверждения внешней загрузки через `ibcmd` не найден. Публичный API, возвращающий точный набор изменённых файлов проекта для `--partial`, также пока не найден; найденные реализации менеджеров синхронизации в core находятся во внутренних пакетах и не подходят под текущие ограничения.
- `IWorkspaceOrchestrator.stopProject(...)` управляет lifecycle проекта EDT и не является API сеанса Designer Agent.
- Источники JavaDoc: [`IApplicationManager`](https://edt.1c.ru/dev/edt/2025.2/apidocs/com/e1c/g5/dt/applications/IApplicationManager.html), [`IExportOperationFactory`](https://edt.1c.ru/dev/edt/2025.2/apidocs/com/_1c/g5/v8/dt/export/IExportOperationFactory.html), [`IDesignerSessionThickClientLauncher`](https://edt.1c.ru/dev/edt/2025.2/apidocs/com/_1c/g5/v8/dt/platform/services/core/runtimes/execution/IDesignerSessionThickClientLauncher.html), [`IThickClientLauncher`](https://edt.1c.ru/dev/edt/2025.2/apidocs/com/_1c/g5/v8/dt/platform/services/core/runtimes/execution/IThickClientLauncher.html).

- [x] Найден публичный API Designer Agent для проверки подключения, закрытия и повторного открытия сеанса; требуется прототип и проверка восстановления в реальной EDT.
- [ ] Найти публичный источник списка изменений проекта для частичного импорта и публичный способ согласовать состояние EDT после внешнего `ibcmd`; если таких API нет, зафиксировать блокер и варианты до разработки основной функциональности.
- [ ] Проверить получение соответствующего `ILaunchableRuntimeComponent`, поведение общего сеанса и восстановление при ошибках/отмене на файловой тестовой ИБ. Полный импорт в пустую ИБ, переход со старой конфигурации с удалением/переименованием, частичный импорт, `config apply` и учёт реквизитов пользователя уже проверены на `8.3.27.2342`.

### 2. Реализация команды

- Реализовать подготовку XML-представления через EDT, вызов `ibcmd`, передачу аргументов без shell, сбор вывода и обработку отмены/ошибок.

### 3. Проверки

- Добавить тесты для построения вызова `ibcmd`, классификации изменений и выбора частичной/полной загрузки.

- Вручную проверить в EDT 2026.1.3 на файловой тестовой ИБ: полную загрузку, частичную загрузку, удаление/переименование, ошибку импорта, отмену, применение конфигурации, восстановление сеанса и последующее состояние штатной синхронизации EDT.

## Критерии готовности

- Команда загрузки работает в обоих режимах с файловой ИБ, привязанной к проекту, и использует `ibcmd` соответствующей версии платформы.
- Конвертация выполняется средствами EDT и не меняет исходники проекта.
- Частичная загрузка передаёт только актуальные изменения; удаление или переименование приводит к полной загрузке.
- Импорт автоматически сопровождается применением конфигурации; принудительное завершение сеансов не включается.
- Сеанс агента/сервера возвращается в исходное состояние после любого исхода операции.
- После успеха внутреннее состояние синхронизации EDT соответствует состоянию базы.
- Ошибки, отсутствие `ibcmd` и невозможность безопасно выполнить операцию не приводят к скрытому переключению на штатную загрузку или другую базу.
